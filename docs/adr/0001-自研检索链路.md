# ADR 0001：主链路不引入 LangChain / LlamaIndex / LangGraph

- **状态**：已采纳
- **日期**：2026-11-19

## 背景

RAG 框架能省掉胶水代码，但也把“切分、召回、融合、引用”的细节藏进抽象层。
本项目的第一目标是**能讲清每一步为什么这么做**，第二目标才是开发速度。

## 决策

主链路只用 `FastAPI + pydantic + SQLAlchemy + pgvector + httpx`；
切分、BM25、RRF、引用校验全部自研，对外保留 `LLMPort` / `EmbeddingPort` /
`RerankerPort` / `RetrieverPort` 四个接口。

## 后果

**好处**

- 每一步都可解释、可单测：`split_document`、`_fuse`、`citation_accuracy` 都是纯函数。
- 没有框架版本升级导致的隐式行为变化。
- 换模型/换存储只影响一个 Port 的实现。

**代价**

- 文档解析器、任务调度等“脏活”要自己写（PDF 解析放到 Phase 4）。
- 缺少生态里的现成优化（例如流式回调管理），需要自己实现 SSE。

## 对应代码

- `src/chunk.py`（切分）、`src/bm25.py`（检索）、`src/retrieve.py`（RRF）
- `src/rerank.py`（`RerankerPort`）、`src/pipeline.py`（编排）
