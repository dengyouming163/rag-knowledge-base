# ADR 0006：发布存 chunk_id 快照，回滚切指针

- **状态**：已采纳
- **日期**：2026-11-19

## 背景

运营更新文档后需要“发布”控制上线时机；上线出问题时需要分钟级回滚。
若采用“复制一份数据”的方案，存储翻倍、复制耗时且两份数据可能不一致。

## 决策

- 发布时只存 **`chunk_id` 列表 + 摘要**（`kb_versions.snapshot`），正文仍只有一份；
- `knowledge_bases.active_version_id` 指向当前生效版本；
- 部分唯一索引保证同库同一时刻只有一个 `published`；
- 回滚 = 切指针 + 用该版本的 `chunk_id` 列表固定检索集合（`version_chunk_ids` 过滤）。

## 后果

**好处**

- 发布/回滚是毫秒级的元数据操作，不搬数据。
- 回滚后新增的块自动不可见，语义清晰。
- 历史版本可审计（何时、谁、包含哪些块）。

**代价**

- 每次固定版本检索多一个 `chunk_id = ANY(...)` 条件；ID 列表到十万级会拖慢查询，
  届时需改为 `kb_version_chunks` 关系表 + JOIN。
- 快照不含正文，若正文被物理删除，旧版本无法完整还原（当前接受，配合软删除更稳）。
