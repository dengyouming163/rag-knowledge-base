# ADR 0004：子块检索、父块补上下文

- **状态**：已采纳
- **日期**：2026-11-19

## 背景

分块大小是一对矛盾：

- 块小 → 向量更聚焦、召回准，但给模型的上下文碎片化；
- 块大 → 上下文完整，但向量被稀释，一句话的问题会匹配到一整章。

## 决策

两级结构：

| 级别 | 大小 | 有向量 | 参与 BM25 | 用途 |
|---|---|---|---|---|
| 子块 | 200–800 token | 有 | 有 | 被检索、出现在引用里 |
| 父块 | 整节，上限 1500 | 无 | 无 | 命中后补上下文 |

引用 ID 仍用子块；`content_hash` 带 `p`/`c` 角色前缀，避免父子同文被唯一约束覆盖。

## 后果

**好处**

- 召回精度与上下文完整度解耦，调小分块不再牺牲答案质量。
- 父块不建向量，不参与排序，不会挤占 top-k。

**代价**

- 存储多一份正文；查询多一次批量取父块（用 `WHERE chunk_id = ANY(...)` 避免 N+1）。
- 超长章节（> 1500 token）需要三级切分或按预算裁剪，目前是截断。

## 对应代码

- `src/chunk.py`（`split_document` 生成父子块）
- `migrations/versions/0004_parent_id.py`（`parent_id` / `is_parent`）
- `src/store_pg.py`（`is_parent = false` 过滤）
